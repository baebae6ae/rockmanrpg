# 균열 회수반

균열에서 나온 것들을 회수하는 아홉 대원의 **횡스크롤 육성 액션 RPG** (개인 제작, 비상업).

메이플스토리식 사냥·성장 구조 위에, 보스를 잡아 그 무기를 얻고 약점 상성으로
푸는 록맨식 전투 구조를 얹는다.

## 현재 상태

**몰이사냥 모드 플레이 가능** — `?horde` 로 접속하면 바로 들어간다.
캐릭터 선택 · 레벨업 무기 선택 · 보스 선택(약점 사슬) · 서포트 유닛까지 돈다.

- 배포: <https://baebae6ae.github.io/rockmanrpg/?horde>
- 설계 문서: [`docs/DESIGN.md`](docs/DESIGN.md)

## 개요

| 항목 | 내용 |
|---|---|
| 엔진 | TypeScript + PixiJS (웹) |
| 기준 화풍 | 록맨 X4 (PS1) 정도의 밀도 — 내부 해상도 320×240, 정수배 스케일링 |
| 플레이어블 | 회수반 아홉 대원 — 못·종·불씨·거울·바늘·반딧불·도끼·작살·사슬 |
| 적 | 개체 여덟(보스) + 잡몹 일곱 |
| 멀티플레이 | 없음 (싱글플레이 전용) |
| 입력 | 키보드 + 터치 (모바일에서 직접 플레이하며 확인) |

## 핵심 설계 원칙

1. **콘텐츠는 코드가 아니라 데이터다.** 캐릭터·스킬·적·보스 패턴 추가에 코드 수정이 필요하면 설계가 틀린 것이다.
2. **코드는 에셋 경로만 안다.** 스프라이트 교체가 경로 변경만으로 끝나야 한다.
3. **스프라이트 규격을 먼저 고정한다.** 생성된 도트와 나중에 그릴 도트가 동일 규격(고정 캔버스 64×64, 발바닥 하단 중앙 정렬)을 쓰므로, 교체가 파일 교체만으로 끝난다.
4. **물량은 티어로 나눈다.** 전부를 같은 품질로 만들려 하면 아무것도 완성되지 않는다.

## 도트

캐릭터·적 스프라이트는 전부 코드로 생성한다(`tools/`). 손으로 찍지 않는 이유는
품질보다 **일관성** 때문이다 — 얼굴 하나를 고치면 41프레임 아홉 벌이 같이 바뀐다.

| 파일 | 하는 일 |
|---|---|
| `tools/lib/crewart.ts` | 재질·램프·형태광 — 화풍의 실체가 여기 있다 |
| `tools/lib/crew.ts` | 대원 아홉의 몸·머리·장비 |
| `tools/lib/crewanim.ts` | 대원이 공유하는 자세표 |
| `tools/lib/foe.ts` | 개체 여덟과 잡몹 일곱 |
| `tools/crew-preview.ts` | 대원 미리보기 (`SC=배율 CO=열수 PO=포즈`) |
| `tools/foe-preview.ts` | 개체 미리보기 (`SC=배율 AC=동작`) |

`npm run build` 가 생성 → 데이터 검증 → 번들을 한 번에 돈다. 검증이 실패하면
배포되지 않는다.

## 저작권

캐릭터·적·무기 디자인과 스프라이트는 전부 이 저장소에서 만든 것이다.
장르와 전투 구조는 록맨 시리즈에서 영향을 받았으며, Rockman / Mega Man 및
관련 상표는 캡콤의 것이다. 이 프로젝트는 캡콤과 아무런 관련이 없다.
